# FD-006 Comprehensive Field Table

Ticket: FD-006  
Epic: Field Lineage Documentation  
Scope: final consolidation of FD-001 through FD-005; documentation only.

## How To Use This Table

This is the single searchable database-field dictionary for the current EasyETFsAT schema and reporting views. It consolidates the FD-001 inventory with the source, reference, curated, reporting-view, API, and null/zero rules documented in FD-002 through FD-005. The rows are intentionally concise; follow the linked owner artifact when a field needs deeper evidence, SQL examples, parser details, or open-question context.

Important boundaries:

- The table includes one row for every database table/view field listed in FD-001.
- OeKB tax labels and registry names are field labels, not tax advice.
- Unclear reference, FX, adjustment, distribution, correction, or API semantics remain marked as open questions instead of being inferred.
- `STF` is the source/dictionary foundation code, `stiftung` is the semantic/API category key, and `STI` is the reporting-view compatibility alias.

## Open Questions Carried Forward

- `REFCCY` and `REFCTR` have schema/documentation meaning, but their authoritative row-source or seed policy is not established in the current application flow.
- Deeper tax-law semantics beyond registry labels remain outside the current documentation and should not be inferred from K-codes alone.
- `TAXADJ.TAXCOD = AKC`, `TAXCOR.TAXRSN = KID`, and `SECDIV.SECFLWAMT` need business confirmation before broader semantics are assigned.
- `V2_TAXDATEUR` currently uses exact-date FX matching; SE-008 approves nearest-prior ECB lookup as future behavior, but no schema/view/API implementation has changed in this documentation ticket.
- Current API amount serialization is JSON numeric float conversion; decimal-safe string semantics would need a separate compatibility ticket.
